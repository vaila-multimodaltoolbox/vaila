vailá - multicam_recorder

📋 Module Information

Category: Tools

File: vaila/multicam_recorder.py

Version: 0.4.5

GUI Interface: ✅ Yes

CLI Interface: ❌ No (GUI only; prints an equivalent CLI command per camera)

📖 Description

Records video from N cameras simultaneously through a simple Tkinter GUI, replacing hand-typed per-camera ffmpeg commands launched in parallel from the shell. Each camera is captured with its own ffmpeg subprocess using stream copy (-c:v copy) — no re-encoding, so quality and CPU usage match manual capture exactly.

  • Cross-platform camera detection: /dev/video* on Linux, ffmpeg avfoundation listing on macOS, ffmpeg dshow listing on Windows
  • Per-camera resolution/fps: editable pickers, best-effort probed via OpenCV
  • Single Start/Stop toggle for every selected camera
  • Graceful stop: sends ffmpeg's interactive q command on each process's stdin so every .mp4 is finalized correctly
  • Fault isolation: a disconnected/hung camera never blocks stopping the others
  • Session output layout: <output_dir>/<session_name>_<timestamp>/cam<N>_<session_name>.mp4 (.mp4 so recordings are directly readable by vailá's Markerless 2D tools)
  • Live preview: every detected camera previews automatically in one small mosaic window, kept live even while recording (via a low-res JPEG ffmpeg also writes)
  • GUI→CLI mirror: prints the exact equivalent ffmpeg command for each camera on Start

🚀 Usage

GUI: select Record Cameras in vailá's Video and Image tools, then pick cameras, output directory and session name, and click Start Recording.

Standalone:

uv run python vaila/multicam_recorder.py

🔧 Main Functions

  • enumerate_cameras — Detect available cameras per OS
  • build_record_command — Build the per-OS ffmpeg argv (stream copy)
  • format_record_cli_command — Render an argv as a copy-pasteable shell command
  • build_session_dir / build_output_filename — Output naming
  • MulticamRecorderController — Owns the live ffmpeg subprocesses (start/stop/watchdog)
  • MulticamRecorderApp — Tkinter GUI
  • run_multicam_recorder — GUI entry point

⚠️ Known Limitations (v1)

  • Windows DirectShow duplicate device names (two identical webcam models) are disambiguated via the device's @device_pnp_... alternative name, not a friendlier label.
  • No hardware frame-level synchronization between cameras — relies on near-simultaneous process launch, same as manual &/wait shell capture.
