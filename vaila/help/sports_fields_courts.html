Soccer Field Kiki (49 KP) & De-overlapped Coincident Keypoints

Use --type kiki (or load vaila/models/soccerfield_kiki.csv) to visualize all 49 reference points, indices 0..48 (32 pitch line intersections [0..31] plus 17 3D/pitch features [32..48]: corner flag tops at z=1.5 m, goal post tops at z=2.44 m, goal net ground points, plus the center spot point 48 at (0,0,0)).

Center field spot (point 48): Explicitly marks the central point inside the center circle at (X=0, Y=0, Z=0), next in numerical order.

Differentiated position & orientation: Points sharing coincident (x, y) ground coordinates (corner ground points 0, 5, 24, 29 vs corner flag tops 38, 39, 46, 47, or goal post bases vs tops) are rendered with separated offsets, horizontal orientation, and dotted leader lines connecting badges to markers so that neither markers nor text labels collide.

Goal post vs net separation: Goal post labels and net points are drawn backwards (“para trás”, behind the goal line) avoiding crossing or encroaching into the penalty area.

Penalty arc (“meia lua”) geometry

Law 1 / the FIFA Football Stadiums Guidelines define the penalty arc as the part of a circle of radius 9.15 m centred on the penalty mark that falls outside the penalty area. Its two endpoints are therefore not free parameters: they are the intersections of that circle with the penalty-area line.

penalty_arc_geometry() computes those endpoints from that definition rather than reading them from the model, so the drawn arc always starts and ends exactly on the penalty-area line. On a regulation 105 x 68 m pitch the penalty-area line is 5.5 m from the penalty mark, so the half-angle is theta = arccos((16.5 - 11) / 9.15) = 53.0518° and dy = sqrt(9.15² - 5.5²) = 7.312489 m.

The arc radius is resolved in this order:

  1. the distance from the penalty mark to a stored *_penalty_arc_*_intersection point, which keeps non-uniformly scaled models (small-sided pitches) consistent with their own stored geometry;
  2. the model's own centre-circle radius, which the norm makes equal to the arc radius (this is the path taken by soccerfield_kiki.csv, which stores no arc keypoints);
  3. the regulation 9.15 m.
*_penalty_arc_top is the arc apex, at 11 + 9.15 = 20.15 m (and 105 - 11 - 9.15 = 84.85 m), not a point on the penalty-area line.

Points 10, 11, 18 and 19: Kiki versus FIFA Dataset

The two modes deliberately share the index order but no longer conflate two different purposes:

  • Soccer Field Kiki — 49 KP is the visual/calibration model. Points 10/11 (left) and 18/19 (right) are the four visible meetings between the penalty arcs and penalty-area front lines: (±35.95, ±7.312489) in the centred frame. Their orange markers therefore sit exactly on the ends of the white arcs.
  • FIFA Dataset — 32 KP remains compatible with the existing Roboflow/Supervision training schema. Its same indices are virtual subdivision anchors at the goal-area Y levels (±35.95, ±9.16); changing those coordinates would invalidate existing YOLO labels and trained models.

The Kiki CSV names the four visible points explicitly as *_penalty_arc_*_intersection. The numbered badge is offset slightly from its orange marker so the badge does not cover the actual intersection.

Interactive Calibration Keypoint Editor

Button Calib Keypoints (in the top toolbar):

  1. Click-to-Add (Define Label Name): Left-click anywhere on the pitch to capture coordinates and immediately open the definition dialog with the Label Name pre-focused. Type the name, choose or type height z (with presets 0m Ground, 1.5m Flag, 2.44m Crossbar), and press Enter to create.
  2. Direct Coordinates / Manual Entry: A dedicated section in the Editor window allows typing coordinates directly (X, Y, Z, label name, point number) without clicking, with quick coordinate presets (Center, Left Goal, Right Goal, Ground, Flag, Bar) and instant + Add Keypoint (From Coords). Selecting any keypoint from the list populates the form for rapid editing and updates.
  3. Augment existing models: Add new custom reference points on top of any loaded model (e.g. benches, camera poles, corner flags).
  4. Create from scratch: Use Create From Scratch (Clear All) to hide reference points while keeping pitch markings visible, allowing you to build a calibration model from zero.
  5. Save Model CSV: Export the keypoints to CSV for direct use in DLT3D, REC3D, getpixelvideo, and readcsv.py.
  6. Save Model C3D: Export the keypoints directly to a standard .c3d file for inspection in 3D viewers.
  7. View in 3D: Instantly launch complete 3D soccer field visualization in native Matplotlib (plot_calibration_model_3d) with 3D field lines, regulation 3D goals (vertical posts, crossbars, net depth frames and back supports), 4 corner flagpoles with pennants, keypoint drop lines (Z→0), and human-friendly box aspect ratio (daspect) control.

Responsive 2-Row Toolbar

To prevent buttons from falling outside the visible window area on standard resolution displays (≥ 800 px width), run_soccerfield organizes controls into two clear, structured rows:

  • Row 1 (Field & View): Load Default Field, Load Custom Field, Surface Color, Hide/Show Reference Points, Show/Hide Axis Values, Heatmap, Help.
  • Row 2 (Tools & Calib): Load Markers CSV, Select Markers, Load Scout CSV, Scout Filters, Create Manual Markers, Clear All Markers, Calib Keypoints (teal), Export REF3D… (blue).

In the Calibration Keypoint Editor dialog, window dimensions are set to 780x640 with listbox height 6 and minimum constraints, ensuring all action buttons at the bottom remain permanently anchored and visible.

3D Environment Verification (plot_calibration_model_3d, showc3d, readcsv, viewc3d_pyvista)

Soccer field calibration keypoints can be checked in full 3D spatial environments:

  • plot_calibration_model_3d (Native Matplotlib): Built into drawsportsfields.py for calibration model building. Renders full 3D pitch markings, 3D regulation goals (posts [traves] and crossbars [travessões] up to 2.44 m, rear net supports), 4 corner flagpoles (1.5 m), keypoint drop lines connecting elevated points to the turf (Z=0), camera angle presets (Isometric, Touchline, Behind Goal, Top-Down Plan), and human-friendly daspect control (4.5x Z toggleable to 1:1 true scale).
  • showc3d.py (Matplotlib): Automatically adapts to soccer field scale (105x68m), renders regulation pitch boundary, halfway line, center circle, and 3D point labels with toggle support.
  • viewc3d_pyvista.py (PyVista): Renders pitch turf plane and white lines at ground level, auto-enables labels for calibration models, and provides interactive point picking.
  • readcsv.py: Recognizes calibration model CSV files directly, passing keypoint coordinates to your choice of 3D visualizer (PyVista, Open3D, or Matplotlib).

FIFA Dataset labeling reference (new)

Use --type fifa_dataset when your goal is to label new broadcast frames/videos for the 32-keypoint pitch dataset used by vaila.fifa_dataset_builder. This mode draws the same FIFA field and overlays:

  • the canonical keypoint order 0..31 (exact zero-based YOLO-pose order),
  • short semantic names near each point for human QA,
  • a footer reminder that ordering matches dataset/getpixelvideo export.

This reference is intended to reduce keypoint index swaps while clicking in vaila/getpixelvideo.py.

Export REF3D for DLT3D

Button Export REF3D… (after a field model is loaded):

  1. Multi-select control points from the loaded model (or the 32 FIFA dataset keypoints when --type fifa_dataset).
  2. Choose p-index base 0 (default, and the vailá standard: getpixelvideo.py, dlt3d.py and rec3d*.py all number points from p0) or 1 (legacy only, for interoperability with 1-based datasets).
  3. Saves *.ref3d, *.ref3d_map.csv, and optional *_pixel_template.csv.

The dialog header states how many reference points the loaded model exposes and their label range, so the count cannot be confused with the last label (the Kiki model has 49 points labelled 0..48, not 48 points).

Because dlt3d.py pairs pixel and reference points by numeric index, a reference file exported with a different base than the pixel file would pair pN with pN where pN-1 was meant; since 0.4.3 dlt3d.py detects that exact shift-by-one and refuses the run instead of returning a plausible but wrong calibration.

Workflow: mark the same pN order in getpixelvideo → dlt3d.py (pixel + .ref3d) → .dlt3d for rec3d_one_dlt3d.py. (fifa_to_dlt.py is the alternate path from FIFA cameras/*.npz, not this REF3D file.)

Note: All sports are unified under vaila/drawsportsfields.py. Each surface has a dedicated plot_* function registered in SPORT_REGISTRY. To add a new sport, write a plot function, add a model CSV to vaila/models/, and register one entry. For publication-quality diagrams and alternative styles see sportypy or mplbasketball.

CSV format

Columns: point_name, point_number, x, y, z (metres). Soccer models must include all points required by soccerfield_ref3d.csv. Simpler models need at least the four corners bottom_left_corner, top_left_corner, bottom_right_corner, top_right_corner.
