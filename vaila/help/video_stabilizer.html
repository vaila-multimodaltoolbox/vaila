Video Stabilizer

Category: Tools → Video and Image
Version: 0.4.5 · Updated: 23 September 2026
Author: Paulo R. P. Santiago
GUI: C_B_r2_c2, between Compress Video and Make Sync file
CLI: uv run vaila/video_stabilizer.py (from repo root) or python -m vaila.video_stabilizer

Stabilize a video using physically fixed pixel markers from getpixelvideo. Metric coordinates are optional for visual stabilization. The default similarity transform preserves shape with translation, rotation and uniform scale. The optional visual homography model adds a full 8-DOF projective warp when perspective motion remains.

GUI workflow

  1. Open Video and Image → Video Stabilizer.
  2. Select the video and its wide marker CSV. Choose an optional output base directory, or leave it blank for a method-named timestamped directory beside the video.
  3. Enter static marker IDs and optional priority anchors. For the tatame, use static markers all and anchors 8-13.
  4. Use visual without a TOML; hybrid adds metric floor diagnostics. Click Stabilize (Ctrl+Enter), or Sweep all methods to rank the grid and render its best candidates. The equivalent CLI is printed with quoted paths.
  5. Open report to inspect per-marker motion before/after.

visual vs hybrid vs floor-lock, in plain terms

All three modes stabilize the video the same way: fit a shape-preserving transform (similarity or affine) from your --stabilization-markers pixel positions and warp every frame so the scene stops shaking/panning/zooming. The difference is only about extra metric (real-world) diagnostics:

  • visual (default) — pixel-only, no TOML needed. Use this if you just want a steady video and don't care about real-world distances. Right choice for most users.
  • hybrid — the exact same visual stabilization as visual, plus an independent floor homography (pixel ↔ real-world meters, from --geometry-config's TOML and --metric-markers) fit per frame, purely for diagnostics. Writes two extra files, floor_homographies.npz and floor_diagnostics.csv, so you can check floor-fit quality (RMSE, condition number) or convert floor-plane pixels to meters later. The stabilized video itself looks the same as visual with the same model/canvas/stabilization-markers. Requires a TOML with real-world positions for your metric markers (the tatame example's vaila/models/planar_targets/tatame_1x1m.toml defines the mat's known 0.96 m module) and --metric-markers naming which CSV marker IDs correspond to those known points.
  • floor-lock — warps each frame with the relative floor homography itself, so the floor plane stays pixel-exact across frames. Deliberately distorts anything not on the floor plane (people, walls, columns). Only use it for planar measurement work where you accept that tradeoff.

No calibrated TOML for your scene, or don't need metric floor diagnostics? Use visual — simpler, fewer inputs. hybrid only makes sense once you have a geometry TOML for that specific camera setup (see planar_geometry_tracker for how to build one).

The resizable child window stays above its parent. A single worker handles encoding; Tk receives progress through a queue. Cancel or closing requests a stop at a safe frame boundary. Audio mux finishes its current step first. Completed files remain available; retry with the same base path after cancellation and the interface creates a new method-suffixed directory. Help and Open report launch local HTML in your browser.

Tatame example

The supplied portrait tatame clip has 331 frames and audio. Markers p0–p7 are fixed floor points on a 0.96 m interlocked module; p8–p13 are fully observed pixel-only upper/background points. They do not need world coordinates.

uv run vaila/video_stabilizer.py \
  --video tests/video_stabilizer/tatame.mp4 \
  --markers tests/video_stabilizer/tatame_markers.csv \
  --stabilization-markers all --anchor-markers 8-13 \
  --mode visual --model homography --canvas union

uv run vaila/video_stabilizer.py \
  --video tests/video_stabilizer/tatame.mp4 \
  --markers tests/video_stabilizer/tatame_markers.csv \
  --geometry-config vaila/models/planar_targets/tatame_1x1m.toml \
  --metric-markers 0-7 --sweep

Both commands run from the repo root. python -m vaila.video_stabilizer ... (same flags) works identically for package-module invocation.

The full 866-combination sweep on this updated fixture ranked visual-homography-rlsq-savgol-refauto-mkall-anc8-13w4 first. Its marker RMS was 3.43 px at the top, 6.27 px in the middle and 6.28 px at the bottom. The old p0–p7 similarity baseline measured 3.78 px at the bottom but had no top or middle marker coverage, so it cannot support a whole-frame stability claim. Use the montage for the final visual choice; these values are marker diagnostics, not pixel-domain image quality.

Flags, one at a time (plain language)

  • --video — path to the shaky source video.
  • --markers — the wide CSV from getpixelvideo: one row per frame, columns pN_x/pN_y per marker ID N. The fixed points the algorithm tracks to figure out how the camera moved.
  • --output-dir — where results go. Leave blank to auto-create a fresh method-named timestamped folder next to the video. If you pass --output-dir, the CLI and GUI append the method slug and then pick _v2, _v3, ... instead of overwriting — no need to pick a fresh empty folder by hand. (Programmatic callers of run_video_stabilizer() directly still get the strict original behavior: FileExistsError if the directory isn't empty — pointing --output-dir at the same folder as --video/--markers is still a bad idea either way.)
  • --mode — visual, hybrid, or floor-lock; see the comparison above.
  • --model — the shape of transform fit per frame. similarity (default) only allows translation + rotation + uniform zoom, so proportions stay true. affine also allows shear and different horizontal/vertical scale. homography adds perspective with eight degrees of freedom; it can stabilize projective motion but may deform content at different depths.
  • --estimator — how the per-frame transform is fit. robust-lsq (default) uses every marker but down-weights ones that look noisy/inconsistent that frame. ransac instead discards correspondences it judges outliers entirely — more aggressive, and empirically worse when markers are sparse/occluded (see the tatame finding above).
  • --stabilization-markers — which marker IDs to use for the visual fit. all (default), or a list/range like 0-7,10,12-14.
  • --anchor-markers — a subset you trust more, given extra weight (--anchor-weight, default 2.0) in the fit. Optional.
  • --hybrid-imputed-weight — relative weight for trusted floor-reconstructed controls; default 0.25 keeps manual clicks dominant.
  • --metric-markers — only used in hybrid/floor-lock: marker IDs that also have known real-world coordinates in --geometry-config's TOML, used for the floor homography fit. Ignored in visual mode.
  • --geometry-config — TOML describing real-world (metric) positions for a subset of markers on a flat plane. Required for hybrid/floor-lock; optional in visual (diagnostics only, no effect on the stabilized video).
  • --floor-estimator — robust-all keeps declared controls and reweights noisy clicks; ransac can reject controls.
  • --reference — which frame's marker positions become the fixed target every other frame is warped toward. auto (default) picks a real frame with good visibility/spread near the temporal middle; first forces frame 0; frame:N picks an exact index.
  • --smooth — light temporal smoothing of fitted transform parameters before warping. savgol (default), lowpass, or none. Usually a small effect; try none only if smoothing seems to lag fast motion.
  • --canvas — output frame size. union (default) grows the canvas to fit every warped frame's corners so nothing crops; original keeps the source's exact size (may crop warped edges); crop picks a fixed centered rectangle guaranteed to stay inside every frame (no black borders, smaller field of view).
  • --border — border fill for empty canvas area. Always black currently; no auto-zoom or content-aware fill.
  • --debug-overlay — also render a side-by-side diagnostic video with marker IDs, reference targets, and residuals.
  • --no-audio — skip copying the source audio track.
  • --sweep — evaluates 432 visual combinations without geometry, or 866 with geometry, then renders only the requested top candidates.
  • --sweep-grid — TOML arrays under [sweep] can override modes, models, estimators, smooth, references, stabilization_markers, anchors, hybrid_imputed_weights and floor_estimators.
  • --sweep-render-top — positive count or all.

Geometry and gaps

Every usable frame maps directly to one fixed real reference, preventing chained drift. Auto reference prioritizes anchor visibility, marker count, spatial spread and proximity to the temporal median configuration; it never invents averaged reference coordinates. Dense marker clusters receive less aggregate weight; priority anchors receive extra weight.

Similarity needs two non-coincident correspondences; affine needs three non-collinear points; homography needs four non-collinear points. Missing coordinates and sparse rows are supported without shortening the video. Gaps interpolate translation, unwrapped rotation and log-scale; leading/trailing gaps propagate the nearest valid transform. Each fallback is logged. Frame IDs must be unique nonnegative integers within the source timeline.

Hybrid fits independent world-XY→pixel floor homographies. p8–p13 are never floor controls unless explicitly declared in both geometry and metric selection. Missing floor fits are marked unavailable/NaN. Trusted fits may reconstruct missing controls at reduced weight. Projected coordinates are never clamped.

Floor-lock is planar-only: it deliberately warps with relative floor homographies and can distort people, walls and columns. Missing fits use nearest-fit propagation. It is unsmoothed and never auto-selected.

Region diagnostics split canonical marker Y coordinates into equal top, middle and bottom thirds. They measure only whether digitized fixed points hold still. Every CSV marker counts, including markers left out of --stabilization-markers (also reported as the held_out row), so a subset fit cannot hide off-plane drift. Regions without any marker are skipped; the worst-region score uses covered regions only. The metric cannot see motion between markers. Runs rank by largest regional marker RMS, then regional mean and scale deviation. The sweep skips grid values whose marker/anchor IDs are not in the CSV and validates --sweep-render-top before triage. Inspect the montage before selecting a method.

A sweep writes sweep_ranking.csv, sweep_report.html, sweep_best_command.txt, sweep_montage.mp4, no-video artifacts under triage/, full artifacts under renders/, and rank-prefixed MP4 files in one flat videos/ directory.

Final matrices and tx/ty include the constant canvas translation; raw parameters do not. Similarity matrices have last row [0,0,1]. Imputed counts are zero. Floor-lock scalar similarity parameters are not applicable: use the full matrix. Affine matrices additionally encode shear/anisotropic scale. Reference-absent marker displacement is unavailable. Border estimates use geometry, not dark image pixels.

Union never resizes the source image: it expands the canvas and fills genuinely uncaptured areas with black.

Interpretation and media

Parallax between fixed points at different depths can remain under one shape-preserving transform. Judge visual stability by background and total marker displacement, not floor homography RMSE alone. Existing FFmpeg/ffprobe and OpenCV dependencies are used. Audio is copied, with AAC fallback if needed, aligned to the video start. Audio preservation failure is reported; silent input is valid. Effective average FPS is used for variable-frame-rate inputs; individual variable timestamps are not reproduced. Codec FPS rounding can occur.
