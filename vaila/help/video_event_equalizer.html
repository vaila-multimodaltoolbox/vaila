Video Event Equalizer

Version: 0.4.15 · Updated: 2026-11-08 · Category: Tools

GUI: Frame C → Make Sync file → Equalize by events (RIFE)

CLI: uv run --no-sync python -m vaila.video_event_equalizer --help

Equalize two or more camera videos using three corresponding events each and local CUDA RIFE. The first (reference) camera sets the grid; every other camera is aligned to it. Outputs use a shared grid with configurable FPS and frame count; CSV maps identify original and generated images in both cameras, including the reference.

Three or more cameras

Repeat --source and --source-events together, in the same order. Each camera gets its own three events and its own video, named <role>_<video>_equalized.mp4:

uv run --no-sync python -m vaila.video_event_equalizer \
  --reference /path/to/c2_16mm_left.mp4 --reference-events 1,9,22 \
  --source /path/to/c1_main.mp4 --source-events 1,9,19 \
  --source /path/to/c3_top.mp4 --source-events 1,8,20 \
  --output-dir /path/to/results

The manifest lists the cameras as reference, source, source_2, source_3, and so on, each with its own *_frames.csv. The FreeKiki one-click reads only reference and source. The GUI has Add camera and Remove for the same cameras, one table row each; the window scrolls vertically and horizontally (wheel; Shift + wheel). GUI Run prints the standard >> vaila/video_event_equalizer: Equivalent CLI banner (uv run --no-sync vaila/video_event_equalizer.py ...). Two different files are required; the same video twice is refused.

See setup, fields, example and limitations.

Output FPS and frame count

  • Leave Output FPS and Output frame count blank to keep the reference grid.
  • FPS only: N = round_half_up(reference anchor span × FPS) + 1. Buttons 60 and 120 fill FPS. Decimal 29.970 = 2997/100; 30000/1001 is the distinct NTSC rate.
  • Count only: use that exact count at the reference FPS.
  • Both: choose FPS and count independently, changing playback speed.
  • FPS must be positive and finite; count must be an integer ≥3. FPS-only requests calculating fewer than 3 frames are rejected.

Click Preview, review exact/decimal FPS, frame count, original/generated counts per camera, first-to-last duration (N−1)/FPS, file duration N/FPS, and change relative to the reference anchor span. Then click Run. Editing any field requires a new preview; probing uses a worker.

Start/end occupy frames 1 and N. Contact is 1 + round_half_up((reference_contact − reference_start) / (reference_end − reference_start) × (N−1)), clamped to 2…N−1. Preview shows its rounding/clamping adjustment in seconds and its total time change relative to the reference. Each camera maps its own two segments linearly onto these anchors. All three anchor images are copied exactly; fractional positions use installed CUDA RIFE. Higher FPS creates visual estimates, not acquired measurements.

uv run --no-sync python -m vaila.video_event_equalizer \
  --reference /path/to/c2.mp4 --source /path/to/c1.mp4 \
  --reference-events 1,9,22 --source-events 1,9,19 \
  --output-fps 120 --output-frame-count 85 --output-dir /path/to/results

--dry-run prints the same plan and full maps as JSON, without loading RIFE or writing output. Export prints the preview first. GUI Run prints the equivalent CLI.

The manifest keeps effective output_fps / output_frame_count and adds requested values, output anchors, rational durations and contact adjustments. CSV maps retain existing columns and add the output parameters and timing audit. reference_frame is an integer on the default grid and may be rational on a custom grid; reference_position always gives the exact rational position. event labels anchors. Counts appear in preview and manifest. Both cameras are preflighted at their own dimensions when interpolation is needed. These controls reuse the installed model without new dependencies or downloads.

Main camera and frame count

Any camera can be the Main: pick the Main button of its row in the window (on the command line, it is --reference). Its events set the contact and the timing, and its video is the reference of the run. The other cameras are mapped onto its timeline.

Frame count from chooses how many output frames there are:

  • main camera (as before): the main camera's own span. The main keeps its frames.
  • shortest camera (reduce): the shortest event span in seconds. Longer cameras are compressed onto it, so they lose frames.
  • longest camera (increase): the longest event span in seconds. Shorter cameras are stretched onto it with RIFE, so they gain generated frames.

The mode only sets the default count: a typed output frame count overrides it. FPS stays the main camera's unless you type Output FPS. Preview prints the target span.

uv run --no-sync python -m vaila.video_event_equalizer \
  --reference /path/to/c1_passe_main.mp4 --reference-events 1,1,26 \
  --source /path/to/c2_passe_16mm.mp4 --source-events 1,1,39 \
  --mode increase --output-dir /path/to/results

Contact on the start or end

When only the start and end of the sync are known, the contact may repeat one of them: 1,1,39 puts the contact on the start, 1,26,26 on the end. The output grid then places the contact on frame 1 or frame N, and the zero-length segment is skipped. Start and end must differ, the contact must lie between them, and every camera must use the same pattern as the reference (all on the start, all on the end, or all with their own contact frame). Mixed patterns are refused.

uv run --no-sync python -m vaila.video_event_equalizer \
  --reference /path/to/c2_passe_16mm.mp4 --reference-events 1,1,39 \
  --source /path/to/c1_passe_main.mp4 --source-events 1,1,26 \
  --output-dir /path/to/results

The reference sets the output frame count: here 39 frames, so the 26-frame camera gets 37 generated frames. Choosing the 26-frame camera as reference instead gives 26 output frames, and the 39-frame camera is compressed onto them.

Sub-frame events (decimals)

Event frames may have decimals, e.g. 2.561,2.561,180.561. Use them when a camera is a known fraction of a frame off, as measured by Chessboard Calib (frame_offsets_subframe in its report). The positions are exact rationals (2.561 = 2561/1000). Every output frame of that camera then falls between two originals, so all its images are generated by RIFE. The anchors are generated too, unlike with whole-number events. Whole-number events behave exactly as before. Every position must stay inside the video (1 ≤ event ≤ frame count). Generated images are estimates, not measurements.

Chessboard Calib prints the whole command when a camera is more than 0.1 frame off and no camera dropped frames. The reference gets events A,A,B; a camera with offset e (camera frame = reference frame + e) gets A+e,A+e,B+e:

uv run --no-sync vaila/video_event_equalizer.py \
  --reference cam06.mp4 --reference-events 2,2,180 \
  --source cam07.mp4 --source-events 1.860,1.860,179.860 \
  --source cam08.mp4 --source-events 2.561,2.561,180.561 \
  --output-dir /path/to/results

Pixel CSVs of the equalized videos use that calibration without --apply-offsets or --subframe, because the videos are already aligned.

Installation and reinstallation

Practical-RIFE 4.25 is optional and no longer installed by default. Install it (about 50 MB) in a folder you choose, then verify CUDA, in an existing vailá CUDA environment:

bash bin/setup_rife.sh --home /big/disk/rife   # portable folder on any disk
bash bin/setup_rife.sh                         # or inside the vailá folder (legacy layout)
# Windows:
pwsh bin/setup_rife.ps1 --home D:\rife

Setup downloads pinned code and model, verifies SHA256 hashes and runs CUDA inference. No new extra, HF login or separate cuDNN installation is required. Repeated setup reuses verified assets.

Choosing and moving the folder. The equalizer reads RIFE from --rife-home DIR, else from the environment variable VAILA_RIFE_HOME, else from the legacy folders in the vailá checkout (.local/third_party/Practical-RIFE/ and vaila/models/rife/train_log/). --rife-dir and --weights override one folder each. A chosen folder without RIFE is an error, never a silent fallback. To copy an installed RIFE to another disk or computer with no network (hashes verified, real CUDA test on the copy):

bash bin/setup_rife.sh --export /other/disk/rife
uv run --no-sync python -m vaila.video_event_equalizer --gui --rife-home /other/disk/rife

A portable folder holds Practical-RIFE/, train_log/ (with flownet.pkl) and setup_manifest.json. Assets remain outside Git. See setup and recovery for offline restore details.
