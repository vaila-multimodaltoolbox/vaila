vailá — Vertical Jump Analysis (vaila_and_jump.py)

Overview

The tool processes CSV files to estimate jump metrics in three modes: Time-of-Flight, Jump-Height, and MediaPipe Pose. It generates plots, calibrated CSVs, and an HTML report. Team batch also creates visual group comparison, Z-score/QC tables, and optional correction of height/flight time from foot-contact frames when CoM timing is inconsistent.

Key Features

  • Automatic y-axis correction for MediaPipe (upward-positive)
  • Robust detection of jump phases (squat, takeoff, peak, landing)
  • Multiple height estimates: CG, flight time, feet-based
  • Power metrics: instantaneous, takeoff, average during propulsion
  • Bilateral foot timing and height comparisons
  • Kinematic Analysis: Valgus Ratio, FPPA, and risk screening

Input Types

  1. Time-of-Flight CSV — columns: mass_kg, time_of_flight_s[, contact_time_s]
  2. Jump-Height CSV — columns: mass_kg, height_m[, contact_time_s]
  3. MediaPipe Pose CSV — vailá naming, landmark columns like nose_x, nose_y, right_ankle_x, right_ankle_y, etc.
    You can use either:
    • Normalized CSV: *_mp_norm.csv (x,y in [0..1]) — recommended
    • Pixel CSV: *_mp_pixel.csv (x,y in pixels)
    Both forms are supported. The script scales to meters using a shank-length factor.

Coordinate System

  • Biomechanics convention: y increases upward. MediaPipe is reoriented accordingly.
  • CG and landmarks are converted to meters via shank-length scaling
  • Normalized CG referenced to average CG over initial frames (default: 10–20)

How to Use

  1. Run via vailá GUI or python vaila/vaila_and_jump.py
  2. On macOS, GUI launch reuses the main Tk window so prompts remain movable and focused.
  3. Choose the target directory with CSV files
  4. Select data type: (1) Time of Flight, (2) Jump Height, (3) MediaPipe
  5. For MediaPipe: enter subject mass (kg), video FPS, and shank length (m).
    Note: FPS can be a decimal (float) for high-speed cameras.
    To avoid prompts, place a vaila_and_jump_config.toml next to your CSV files with:
    [jump_context]
mass_kg = 75.0
fps = 240.0
shank_length_m = 0.40
  6. Review outputs in the generated timestamped folder

CLI (command line)

Same options apply for all data types. Use -d to select the mode:

  • -i — Input: CSV file (mode 3) or directory of CSVs (modes 1 and 2)
  • -c — Config TOML (required for mode 3 MediaPipe)
  • -o — Output directory (optional; default: next to input, timestamped)
  • -d — Data type: 1 = Time of Flight (directory), 2 = Jump Height (directory), 3 = MediaPipe (single CSV + config)
  • --gui — Force GUI mode

Example (MediaPipe, mode 3):

python vaila_and_jump.py -i path/to/file.csv -c path/to/vaila_and_jump_config.toml -o path/to/output/ -d 3

Example (Time of Flight batch, mode 1): -i <dir> -o <out> -d 1. Example (Jump Height batch, mode 2): -i <dir> -o <out> -d 2.

Outputs

  • CSV: <name>_jump_results_<timestamp>.csv (scalars; mode 3)
  • CSV: <name>_jump_timeseries_<timestamp>.csv (one row per frame; mode 3)
  • CSV: <name>_calibrated_<timestamp>.csv
  • PNG: diagnostic and phases plots; stick-figure visualizations (with Time/Height info)
  • PNG: Valgus event analysis with risk metrics (text outside plot)
  • HTML: <name>_report_<timestamp>.html — comprehensive report with risk table
  • Team batch: team_jump_quality_zscores_<timestamp>.csv and a report with height distribution, Z-score matrix, and QC highlights

Calibration Check (read this first)

Airborne, the centre of mass is a projectile, so fitting a parabola to it must return g = 9.81 m/s². This is the only check independent of the two values you type in: gmeasured = 9.81 · (fpsentered/fpstrue)² · (scaletrue/scaleentered). Outside 85-115% of 9.81 the run is flagged calibration_error and the report gives the implied frame-rate and scale corrections plus a *_freefall_check.png figure. The usual cause is entering the playback fps of a slow-motion clip (e.g. 120 when the camera captured at 240): that quarters the measured g.

Jump Height: which number to use

  • height_com_takeoff_ref_m — peak CoM minus CoM at foot-off. The jump height; recommended by QC.
  • height_cg_method_m — peak CoM above standing height. Larger, because the CoM already rises before the feet leave the ground.
  • height_foot_contact_method_m — g·t²/8 from last foot-off to first foot contact. Should agree with the first.
  • height_flight_time_method_m — g·t²/8 over the CoM-baseline crossing interval. Not a flight time; shown only to expose the difference.

Phase Events (not interchangeable)

  • takeoff_frame / landing_frame — CoM crosses its standing baseline, not foot-off/contact.
  • takeoff_frame_foot_contact / landing_frame_foot_contact — last foot-off / first foot contact.
  • takeoff_frame_kinetic — last propulsion frame with a positive modelled GRF.

Kinematic Analysis & Risk Screening

  • Valgus Ratio: Knee Sep. / Hip Sep. The ratio decreases as the knees collapse inward, so < 0.8 indicates a valgus pattern; > 1 means knees wider than hips (varus).
  • FPPA: Frontal Plane Projection Angle, |FPPA| = 180° − angle(HIP-KNEE-ANKLE). The sign is anatomical — the knee offset from the HIP→ANKLE line is projected onto the medial direction of that limb — giving one convention for both sides: positive = valgus (the ACL mechanism), negative = varus. |FPPA| > 10° indicates risk, and valgus and varus are reported as distinct findings.
  • Peak excursions: max_valgus_angle_* and max_varus_angle_* are tracked separately over the 0.2 s post-landing window, plus peak_fppa_deviation_* for the largest deviation in either direction.
  • Robustness: Smart frame search to handle occlusions during Squat phase

Equations

  • Height from flight time: h = g t² / 8
  • Takeoff velocity: v = sqrt(2 g h)
  • Potential energy: Ep = m g h
  • Kinetic energy: Ek = ½ m v²
  • Average propulsion power: P̄ = m g h / tprop — Ek at take-off and Ep at the apex are the same energy (v is derived from h), so they are never summed; total_energy_J = m g h
  • Propulsion work power: P̄work = (m g h + m g dsquat) / tprop
  • Vertical force: F(t) = m [a(t) + g] — valid only in contact; forced to 0 during flight, where the true GRF is zero
  • Instantaneous power: P(t) = F(t) · v(t), from a CoM low-pass filtered at 12 Hz (zero-lag Butterworth) before differentiation
Notes: Use the actual capture FPS for slow-motion recordings (e.g., 240 Hz), not the playback FPS. ffprobe will not tell you this: a retimed slow-motion clip reports its playback rate (a real 240 fps trial reports r_frame_rate = 30.02). If unsure, run once and read the free-fall calibration check, which reports the implied FPS from gravity itself. Normalized CSV is simplest; pixel CSV is supported via scaling. Units: m, s, W, J.

Visão Geral (PT)

A ferramenta processa CSVs para estimar métricas do salto nos modos Tempo de Voo, Altura Medida e MediaPipe. Gera gráficos, CSVs calibrados e um relatório HTML.

Principais Recursos

  • Correção automática do eixo y para MediaPipe (y para cima)
  • Detecção robusta das fases (agachamento, decolagem, pico, aterrissagem)
  • Altura por CG, tempo de voo e pés
  • Potência instantânea, na decolagem e média na propulsão
  • Comparações bilaterais de tempos e alturas dos pés
  • Análise Cinemática: Razão de Valgo, FPPA e rastreamento de risco

Tipos de Entrada

  1. CSV de Tempo de Voo — colunas: mass_kg, time_of_flight_s[, contact_time_s]
  2. CSV de Altura — colunas: mass_kg, height_m[, contact_time_s]
  3. CSV de Pose MediaPipe — nomes vailá, colunas como nose_x, nose_y, right_ankle_x, right_ankle_y, etc.

Sistema de Coordenadas

  • Para MediaPipe: y_biomec = 1.0 - y_tela
  • CG e marcos em metros via escala pelo comprimento da perna (tíbia)
  • CG normalizado em relação à média dos quadros iniciais (padrão: 10–20)

Como Usar

  1. Execute pela GUI do vailá ou python vaila/vaila_and_jump.py
  2. No macOS, a execução pela GUI reutiliza a janela Tk principal para manter os diálogos móveis e com foco correto.
  3. Selecione o diretório com os CSVs
  4. Escolha: (1) Tempo de Voo, (2) Altura, (3) MediaPipe
  5. Para MediaPipe: informe massa (kg), FPS e comprimento da perna (m). Nota: O FPS pode ser um número decimal (float).
  6. Confira as saídas na pasta com timestamp

CLI (linha de comando)

Mesmos argumentos para todos os modos. Use -d para o tipo de dado:

  • -i — Entrada: arquivo CSV (modo 3) ou diretório de CSVs (modos 1 e 2)
  • -c — Config TOML (obrigatório para modo 3 MediaPipe)
  • -o — Diretório de saída (opcional)
  • -d — Tipo: 1 = Tempo de Voo, 2 = Altura, 3 = MediaPipe
  • --gui — Forçar modo gráfico

Exemplo (MediaPipe): python vaila_and_jump.py -i ficheiro.csv -c config.toml -o saida/ -d 3

Saídas

  • CSV: <nome>_jump_results_<timestamp>.csv (escalares; modo 3)
  • CSV: <nome>_jump_timeseries_<timestamp>.csv (uma linha por frame; modo 3)
  • CSV: <nome>_calibrated_<timestamp>.csv
  • PNG: gráficos de diagnóstico e fases; figuras de bastão (com Tempo/Altura)
  • PNG: análise de valgo com métricas de risco (texto fora do gráfico)
  • HTML: <nome>_report_<timestamp>.html — relatório completo com tabela de riscos
  • Team batch: team_jump_quality_zscores_<timestamp>.csv e relatório com distribuição de altura, matriz Z-score e destaques de QC

Análise Cinemática e Risco

  • Razão de Valgo: Sep. Joelho / Sep. Quadril. A razão diminui conforme os joelhos colapsam para dentro, portanto < 0.8 indica padrão de valgo; > 1 significa joelhos mais afastados que os quadris (varo).
  • FPPA: Ângulo de Projeção no Plano Frontal, |FPPA| = 180° − ângulo(QUADRIL-JOELHO-TORNOZELO). O sinal é anatômico — o desvio do joelho em relação à linha QUADRIL→TORNOZELO é projetado na direção medial do membro — com uma única convenção para os dois lados: positivo = valgo (mecanismo do LCA), negativo = varo. |FPPA| > 10° indica risco.
  • Robustez: Busca inteligente de quadros para lidar com oclusões na fase de Agachamento

Equações

  • Altura: h = g t² / 8
  • Velocidade de decolagem: v = sqrt(2 g h)
  • Energia potencial: Ep = m g h
  • Energia cinética: Ek = ½ m v²
  • Potência média: P̄ = m g h / tprop — Ek na decolagem e Ep no ápice são a mesma energia, portanto nunca são somadas
  • Força vertical: F(t) = m [a(t) + g] — válida apenas em contato; forçada a 0 durante o voo
  • Potência instantânea: P(t) = F(t) · v(t)
Observações: Use o FPS correto para tempos precisos. Em câmera lenta, use a taxa real de captura (ex.: 240 Hz), não a de reprodução. Se houver dúvida, rode uma vez e leia a verificação de queda livre: ela informa o FPS implícito. Unidades: m, s, W, J.
