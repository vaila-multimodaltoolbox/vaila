📖 Description

Object detection and tracking using YOLO v26 (latest version) with integrated pose estimation.

Features:

  • Object detection and tracking using Ultralytics YOLO26
  • Graphical interface (Tkinter) for configuration
  • Video processing with OpenCV
  • CSV generation with frame-by-frame tracking data
  • Pose estimation within tracked bounding boxes
  • Automatic GPU detection (CUDA/MPS/CPU)
  • Run modes: track, track+pose (default), track+seg, run_all (track+seg+pose)
  • Single-pass track+pose (v0.3.66): geometric ID stabilize, upscaled bbox ROI, all_id_pose.csv, yolo_reid_links.csv, <stem>_track_pose_overlay.mp4
  • Five automatic bbox keypoint tables: yolo_vaila_center.csv, yolo_vaila_bottom.csv, yolo_vaila_top.csv, yolo_vaila_left.csv, and yolo_vaila_right.csv, using the SAM3/Sapiens2-compatible frame,x1,y1,...,xN,yN schema
  • Segmentation exports (when masks available): yolo_masks_manifest.csv (frame,id,area,mask_png), yolo_contours.json (SAM-style top-level metadata + frames), yolo_masks/; processed_*_seg.mp4 / _all.mp4 via H.264 FFmpeg like bbox outputs
  • Tracking-directory discovery for pose-from-tracking: recursive scan for *_id_*.csv under a chosen root (e.g. vailatracker_*)
  • TensorRT: trtexec args match TRT 10; full stderr on failure; fallback to .pt

🤖 Available YOLO26 Models

🖥️ Headless CLI (track) — export biomechanics CSVs

Run detection + tracking on a video and export the CSVs vailá's kinematics pipeline needs. Ultralytics' own yolo track saves only a video; this subcommand also writes the REC2D/REC3D markers CSV and the per-ID bbox tracks.

uv run python -m vaila.yolov26track track \
  --model /ABS/runs/<run>/weights/best.pt \
  --source /ABS/video.mp4 \
  --class-name person --conf 0.25 --imgsz 1280 \
  --tracker botsort.yaml --max-ids 26 --anchor bottom

Outputs in <video_dir>/processed_yolotrack_<stem>_<timestamp>/ (or --output DIR):

  • <stem>_markers.csv — getpixelvideo point format frame,p1_x,p1_y,...,pN_x,pN_y (one anchor point per player). Feed this into REC2D (rec2d.py) / REC3D (rec3d.py) with your DLT parameters.
  • yolo_vaila_center.csv, yolo_vaila_bottom.csv, yolo_vaila_top.csv, yolo_vaila_left.csv, yolo_vaila_right.csv — five bbox keypoint tables generated automatically with the SAM3/Sapiens2-compatible frame,x1,y1,...,xN,yN schema. Offline ReID identities are used when enabled.
  • {label}_id_NN.csv + all_id_detection.csv — raw per-ID bbox tracks.
  • all_id_detection_reid_maxidsN.csv — class-aware stable bbox table written automatically with --max-ids N; this is the recommended getpixelvideo/downstream input.
  • <stem>_track_overlay.mp4 — annotated H.264 MP4 (never a bulky .avi; --no-save-video to skip).

Flags: --anchor center|bottom|top|left|right|corners (marker point of bbox; default bottom = foot), --max-ids N (preserve all tracklets, then merge into at most N stable IDs per class with reid_markers), --classes 0 32, --vid-stride N, --device auto|cuda|cpu, --conf/--iou/--imgsz.

Automatic class-aware ReID (v0.3.107): setting --max-ids N automatically runs reid_markers' Hungarian + IoU + centroid + velocity merge. The old top-N persistence cap was removed because it discarded fragments before matching. Each label has an independent identity pool. --reid-postprocess remains available for auto-estimation without a fixed limit. See reid_markers.

Kinematics flow: use the same --anchor for every camera and use all_id_detection_reid_maxidsN.csv as the stable identity table when aligning point tracks across views.
