extractpng.py — Video ↔ PNG

Version: 0.4.6
Updated: 30 September 2026
Author: Prof. Dr. Paulo R. P. Santiago

Part of vailá. High-performance video-to-PNG extraction and PNG-to-video creation accelerated by NVIDIA GPU hardware (NVDEC decoding & NVENC encoding via FFmpeg CUDA) with automatic CPU software fallback.

Key Optimizations & Features

  • NVIDIA GPU Decoding (--hwaccel auto|cuda|cpu): Auto-detects NVIDIA GPUs (e.g. RTX 4090) and decodes streams directly on hardware with NVDEC via -hwaccel cuda.
  • Fast Lossless PNG Extraction (-c / --compression 0-9): Defaults to fast level 1 with -pred none, speeding up extraction ~3x while maintaining bit-for-bit lossless pixel parity.
  • Redundant Rescaler Bypass: Skips unnecessary CPU Lanczos/bicubic resampling when target dimensions match native video.
  • Parallel Multi-Video Batching (-j / --workers): Multi-threaded video extraction using ThreadPoolExecutor to saturate NVDEC and CPU cores.
  • NVIDIA NVENC Video Creation: Fast encoding of PNG folders to MP4 via h264_nvenc and hevc_nvenc. Every PNG uses a temporary numbered image2 sequence in natural filename order (frame_2.png before frame_10.png).
  • Stratified Random Frame Sampling (sample subcommand): Extracts $N$ well-spaced, non-contiguous random frames per video (default 20) using stratified jittered sampling to guarantee uniform temporal distribution without clustering. Supports recursive directory scanning (--recursive).

GUI

Frame C → Video and Image → C_B_r1_c1 - Video<-->PNG, or:

uv run vaila/extractpng.py
  1. Check the detected GPU hardware acceleration badge.
  2. Choose mode: Video → PNG / PNG → Video / Select frames / Random sample.
  3. Browse input (output optional).
  4. Select acceleration mode, compression speed, parallel workers, and sampling options.
  5. Click Run (prints copy-paste CLI mirror).

CLI

# Fast GPU extraction with auto-detected CUDA and level 1 compression:
uv run vaila/extractpng.py extract -i /path/to/videos

# Explicit GPU acceleration with 4 parallel workers:
uv run vaila/extractpng.py extract -i /path/to/videos -o /path/to/out --hwaccel cuda --compression 1 --workers 4

# Create video using GPU NVENC hardware encoder:
uv run vaila/extractpng.py create -i /path/to/png_dirs --fps 30 --codec 264_nvenc --hwaccel cuda

# Grab select frames with GPU acceleration:
uv run vaila/extractpng.py frames -i VIDEO.mp4 --frames 0,3,5,7 --hwaccel cuda

# Extract 20 well-spaced random frames per video recursively across subdirectories:
uv run vaila/extractpng.py sample -i /path/to/videos -n 20 --recursive

Notes

  • FFmpeg -hwaccel cuda is placed before -i (input option).
  • Default PNG pattern: %09d.png (extraction; creation includes every PNG in natural order).
  • PNG → Video accepts any directory of .png files, or immediate subfolders that contain them. Every PNG in the folder is sorted by filename and joined into one MP4.
  • Random sampling writes vaila_random_samples_<timestamp>/<stem>_random<N>/frame_<number>.png and manifest.csv per video, plus sampling_summary.csv in the output root.
  • Batch extraction generates video_info.txt in each directory detailing FPS and GPU profile.

PNG → MP4 defaults: quality 18 (1–51, lower is better), GOP 1 (every frame independent), no B-frames. CLI: --quality 18 --gop 1. NVENC uses p7/hq VBR CQ; CPU uses slow/CRF. H.264 and H.265 preserve these settings on CPU fallback. Every PNG produces exactly one frame in natural filename order, including gaps and names with spaces. Original dimensions and chosen FPS are preserved; mixed dimensions and odd dimensions incompatible with yuv420p are rejected. MP4/yuv420p remains lossy and cannot restore detail already blurred in the PNG. GOP 1 generally produces larger files.
